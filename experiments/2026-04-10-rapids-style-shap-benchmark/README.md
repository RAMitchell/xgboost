# Current quadrature and timeout policy (2026-11-11)

The current CPU/GPU implementation uses standard Gauss–Legendre mapped linearly
to [0,1]. The historical transformed-node measurements remain archived; a source
or library hash change requires a fresh results directory.

The benchmark defaults to `--prediction-timeout-seconds 600` for each accuracy,
warm-up and timed prediction. Any one over-limit call discards all statistics for
that algorithm/device/model entry. Ten calls under 600 seconds each remain valid
even if their sum exceeds 600 seconds. `--case-timeout-seconds` is a separate,
optional aggregate budget and is unset by default. The payload records both limits
and retains per-call phase/duration records. IPC is outside the prediction timer.
`--prediction-timeout-seconds 0` explicitly disables the per-call limit.

# RAPIDS-Style SHAP Benchmark Models

This directory is used by the paper experiments to define and reproduce the benchmark XGBoost models. Trained model files are intentionally not committed.

## Script

The model metadata is generated by:

```bash
/home/nfs/rorym/anaconda3/bin/conda run -n xgboost \
  python experiments/2026-04-10-rapids-style-shap-benchmark/quadratureshap_rapids_benchmark.py \
  --model all \
  --model-dir experiments/2026-04-10-rapids-style-shap-benchmark/model-cache \
  --models-only \
  --output experiments/2026-04-10-rapids-style-shap-benchmark/models-only-unique-depth.json \
  --out-markdown experiments/2026-04-10-rapids-style-shap-benchmark/models-only-unique-depth.md
```

Use `--force-retrain` to overwrite cached models.

## Committed vs Local Artifacts

Commit the script changes that make this reproducible, but do not commit generated model files or result tables.

Keep local only:

- `model-cache/*.ubj`
- `*.json`
- `*.csv`
- generated `*.md` result tables, unless a small table is deliberately included as paper notes

## Relevant Model Metadata

The paper benchmarks use the `max_unique_feature_depth` column because numerical stress in TreeSHAP-IQ depends on unique feature depth rather than raw tree depth.

## Runtime variability

The benchmark now defaults to 10 timed repetitions after 3 explicit warm-up calls.
An additional untimed prediction is used for accuracy checks before warm-up.
Set `--niter`, `--warmup`, and `--nthread` explicitly for paper runs. JSON retains
every timing sample, sample standard deviation (`ddof=1`), median, quartiles, and
environment metadata. `--out-details` exports those fields to CSV; Markdown also
includes the variability table. Speedups remain ratios of arithmetic means.
Each repetition explains the same rows using the same fitted model. These are
within-process execution repetitions, not independent training runs or confidence
intervals. Cases run sequentially in algorithm/device batches, not interleaved.
The case timeout covers loading, accuracy, warm-up, and all repetitions together.

For the two paper tables, keep `--nrows 1000` for first-order values and use
`--nrows 100 --interactions` for pairwise interactions. `--devices cpu` can restrict
execution to CPU; the default includes CPU and CUDA. Run timings only when the
machine is otherwise quiet and retain the thread count and device selection.

Render existing or new results as mean ± sample SD in Markdown, CSV, and LaTeX:

```bash
python experiments/2026-04-10-rapids-style-shap-benchmark/summarize_runtime_variability.py \
  --inputs <first-order.json> <pairwise.json> --out-dir <output-directory>
```

Older JSON files store population SD (`ddof=0`); the renderer converts to sample
SD using their recorded repetition count. It preserves means, failed cases, and
speedups. It does not invent missing raw samples, quantiles, or confidence intervals.
The original paper data and the targeted 30-repetition rerun are documented in
`experiments/2026-11-10-runtime-variability/README.md`.
